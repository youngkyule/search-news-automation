# '라하뉴스' 신문사 스타일 테마 가이드

ardentnews.co.kr(국내 인터넷 신문사)의 구조를 참고해 Blogger 위에 신문사 느낌의
레이아웃을 구현했습니다. 이 문서는 실제로 적용된 설정을 기록해 둔 것이며,
테마를 초기화하거나 새 블로그에 동일한 디자인을 다시 적용할 때 참고하세요.

## 적용된 구성 요소

### 1. 테마
- **Contempo Light** 사용 (Blogger 테마 갤러리에서 선택)
- ⚠️ "Simple", "Notable" 등 구형/경량 테마는 이 블로그 설정과 호환성 문제로
  글 제목이 아예 렌더링되지 않는 버그가 있었습니다. 테마를 바꿀 때는 반드시
  변경 후 글 제목이 정상적으로 보이는지 확인하세요.

### 2. 카테고리 내비게이션
- 레이아웃 → "페이지 목록(상단)" 가젯(페이지 가젯)을 사용
- 실제 "페이지"가 아니라 각 카테고리의 라벨 검색 URL을 커스텀 링크로 등록:
  - 생활정보 → `/search/label/생활정보`
  - IT/디지털 → `/search/label/IT%2F디지털` (슬래시는 %2F로 인코딩)
  - 이런 식으로 8개 카테고리 전부 등록
- 추가로 소개/문의/개인정보처리방침 페이지 링크도 같은 메뉴에 포함

### 3. 언어 선택 (ardentnews의 국기 아이콘 메뉴에 대응)
- 레이아웃 → 사이드바(상단) → 가젯 추가 → "번역" 위젯 추가
- 스타일: "드롭다운만" 선택, 제목은 비워둠
- 실제로는 화면 왼쪽 상단 ☰(햄버거) 메뉴를 열면 "언어 선택" 드롭다운으로 노출됨
  (Contempo 테마는 모바일 우선 레이아웃이라 사이드바 위젯이 햄버거 메뉴 안에 들어감)

### 4. 커스텀 디자인 (테마 → HTML 편집)
Blogger 테마 커스터마이저의 "CSS 추가" UI는 매우 불안정해서(드롭다운이
제대로 열리지 않는 버그), **테마 → 추가 작업(⋮) → HTML 편집**으로 들어가
`]]></b:skin>` 바로 앞에 커스텀 CSS를 직접 삽입하는 방식을 사용했습니다.
새로 CSS를 추가/수정할 때도 이 방법을 권장합니다.

적용된 CSS 핵심 내용:
- `#header`: 남색(#0d2c6b) 마스트헤드, 흰색 굵은 로고
- `.overflowable-container` / `ul.tabs li.overflowable-item a`: 남색 배경의
  흰색 카테고리 탭 메뉴
- `.post-title`: 남색 굵은 헤드라인
- `.post-labels a`, `.label-name`: 빨간색 라벨 배지
- `.post-body`: 가독성 좋은 본문 폰트 크기/줄간격
- Noto Sans KR 구글 폰트 적용

### 4-1. 로고 이미지 (가운데 정렬, 2026-10-18 추가/수정)
- 로고 원본: `assets/logo.png` (투명 배경 처리, 흰 여백 trim 완료)
  - 생성 방법: `Image.open(webp).convert('RGBA')` 후 거의 흰색(r,g,b>235) 픽셀을
    alpha=0으로 변경 → `img.getbbox()`로 trim → PNG 저장 (Pillow 10.4.0 필요,
    8.2.0은 WebP 디코딩 미지원이라 `pip install --upgrade Pillow` 먼저 실행)
- 호스팅: GitHub 저장소(`search-news-automation`)를 **Public으로 전환**해서
  `raw.githubusercontent.com` URL로 직접 서빙. (무료 익명 이미지 호스팅
  catbox.moe/0x0.st는 네트워크 차단·업로드 중단 등으로 사용 불가했음)
  - 실제 URL: `https://raw.githubusercontent.com/youngkyule/search-news-automation/main/assets/logo.png`
  - 저장소에는 스크립트/설정 파일만 있고 비밀값은 전혀 없음(API 키 등은
    GitHub Secrets에만 존재) → Public 전환에 따른 보안 위험 없음
- 적용 방식: `.Header h1`(및 `.Header h1 a`)의 `background-image`로 삽입하고
  텍스트는 `text-indent:-9999px`로 숨김(SEO용 원래 텍스트는 유지)
  - ⚠️ 주의 1: 홈페이지에서는 `<h1>라하뉴스</h1>`처럼 `<a>` 태그 없이 렌더링되고,
    글 상세/검색 페이지에서는 `<h1><a>...</a></h1>`로 렌더링됨 → 반드시
    `.Header h1`과 `.Header h1 a` 양쪽에 CSS를 적용해야 함
  - ⚠️ 주의 2: width/height를 다른 규칙에서 `!important` 없이 지정하면, 먼저
    있던 `width:auto !important` 같은 규칙에 밀려 적용되지 않음 → 로고 크기
    지정 CSS는 전부 `!important` 사용
  - 로고 원본이 흰 배경용 디자인이라 남색 텍스트가 남색 헤더와 대비가 안
    되는 문제가 있어, `.Header h1`에 흰색 배경(`background-color:#fff`,
    `border-radius`, `padding`, `background-origin:content-box`)을 추가해
    흰 카드 위에 로고가 놓이는 형태로 처리함
  - 스크롤 시 축소되는 `.sticky` 상태와 글 상세 페이지(`.item-view`)는
    더 작은 크기(150×46px)로 별도 지정
- **2026-10-18 수정**: 처음엔 좌측 상단 고정으로 배치했으나, 요청에 따라
  가운데 정렬로 변경. `.Header`/`.blog-name`/`.Header h1`/`.Header p`의
  `text-align`을 `left`→`center`로, `.Header h1`의 `margin`을
  `0`→`0 auto`로 바꾸면 끝(로고 크기 지정 CSS는 그대로 유지).
- 태그라인(블로그 "설명")도 로고 이미지에 적힌 문구와 통일해
  "오늘의 질문, 오늘의 해법" → "오늘의 이슈, 내일의 인사이트"로 변경.
  Blogger 설정 → 기본 → 설명 필드에서 직접 수정(API로도 가능하나 UI가 더 간단).
  `config/site.json`의 `tagline` 값도 함께 갱신해 둠.
  - ⚠️ 이 필드에 **쉼표(,)가 포함되면 "입력이 잘못되었습니다" 오류**가 나며
    저장되지 않음(Blogger 설정 UI의 알 수 없는 검증 버그로 추정). 쉼표 없는
    문장으로 다시 시도하면 정상 저장됨.

### 4-2. 블로그 주소 변경 (2026-10-18)
`searchnews-kr.blogspot.com` → `rahanews-kr.blogspot.com`로 변경
(Blogger 설정 → 게시 → 블로그 주소). 참고:
- `rahanews.blogspot.com`(하이픈 없는 버전)은 이미 다른 사용자가 선점하고
  있어 사용 불가 → `rahanews-kr`로 대체.
- **주소를 바꿔도 BLOGGER_BLOG_ID(숫자)는 그대로 유지**되므로 GitHub
  Secrets의 `BLOGGER_BLOG_ID`나 자동화 스크립트는 수정할 필요 없음.
- Blogger는 주소 변경 시 **이전 주소에서 새 주소로 자동 리디렉션을
  제공하지 않음**(이전 주소 접속 시 "블로그를 찾을 수 없습니다" 오류).
  기존에 공유된 링크/북마크가 있다면 깨짐에 유의.
- 이전 주소(`searchnews-kr.blogspot.com`)로 등록해 둔 Google Search
  Console 속성·사이트맵 제출·색인 요청은 전부 새 주소로 다시 진행해야
  함(별도 속성으로 취급되어 자동 이전되지 않음).
- ⚠️ **레이아웃 → "페이지 목록(상단)"(PageList) 가젯의 메뉴 링크는 주소가
  바뀌어도 자동으로 갱신되지 않음.** 각 카테고리 메뉴가 커스텀 링크(절대
  URL)로 등록되어 있어서, 저장된 href가 예전 주소(`http://searchnews-kr...`)
  그대로 남아있으면 전체 메뉴가 클릭 시 "사이트에 연결할 수 없음" 오류로
  이어짐(2026-10-18 실제 발생·수정). 블로그 주소를 바꿀 때마다
  레이아웃 → 페이지 목록(상단) → 페이지 가젯 수정에 들어가 각 링크를
  전부 새 주소로 바꿔야 함. 참고로 "소개/문의/개인정보처리방침"처럼 실제
  Blogger 페이지 ID가 연결된 링크는 프런트엔드에서 현재 주소로 자동
  보정되어 보이지만(위젯 데이터에 `id` 필드 존재), 레이아웃 편집 화면의
  원본 href 텍스트 자체는 그대로 예전 주소로 남아있으므로 동일하게
  수정해 두는 것이 안전함.

- Blogger는 기본적으로 사이드바에 "애드센스" 가젯 슬롯을 2개 미리 만들어 둡니다
  (레이아웃 페이지의 "광고" 섹션). 애드센스 승인 전에는 비활성 상태로 둡니다.

  발급받은 스크립트를 붙여넣으면 됩니다(가입/승인 절차는 해당 서비스에서 직접 진행).

## 브랜드/도메인 변경 시 체크리스트
사이트명이나 기자 이메일 도메인을 다시 바꾸고 싶다면:
1. `config/site.json`의 `site_name`, `reporters[].email` 수정
2. Blogger 설정 → "제목" 필드를 블로그 관리 화면에서 직접 수정 (API로 변경 불가)
3. `python scripts/backfill_byline.py` 실행 → 기존 글의 바이라인을 새 값으로 일괄 교체
   (내부적으로 기존 바이라인을 지우고 다시 생성하므로 몇 번을 실행해도 안전합니다)

## 참고: Blogger 테마 편집기 UI 관련 팁
- 레이아웃/테마 페이지는 내부적으로 iframe과 Material 커스텀 드롭다운으로
  구성되어 있어, 화면을 보고 좌표를 클릭하는 자동화가 잘 안 맞을 때가 많습니다.
  문제가 생기면 브라우저 콘솔에서 `document.querySelector`로 요소를 직접 찾아
  `.click()`하거나, 가능하면 **HTML 편집**으로 우회하는 것이 가장 안정적입니다.

## ⚠️ 중요 사고 기록: 글 제목이 전부 사라졌던 사건 (2026-10-17)

### 증상
모든 글의 제목이 사라지고(`headline: "제목 없음"`), 라벨도 전부 비어있었음.
테마/CSS/위젯 문제처럼 보였지만 실제로는 **Blogger API 데이터 손상**이었음.

### 근본 원인
`backfill_images.py`, `backfill_byline.py` 같은 소급 적용 스크립트가
`service.posts().update(body={"content": ...})` 형태로 **content 필드만** 보내고
title/labels를 빼먹었음. Blogger API의 `posts().update()`는 **전체 교체(PUT) 방식**이라
body에 없는 필드는 지워짐 → 모든 글의 title/labels가 통째로 사라짐.

**교훈: Blogger API로 글을 update()할 때는 항상 title/labels/content를 전부 포함해서
보내야 한다.** (읽어온 기존 값을 그대로 다시 넣더라도 반드시 포함할 것)

### 복구 방법
GitHub Secrets는 쓰기 전용이라 기존 refresh token/API 키를 다시 볼 수 없었음.
`scripts/get_refresh_token.py`로 새 refresh token을 발급받고,
`scripts/repair_missing_titles.py`로 각 글의 본문(h2 소제목, 키워드 빈도)만 보고
제목과 카테고리를 추론해서 복구함 (Gemini 등 외부 API 호출 없이 본문 정보만 사용).

### 별개로 발견된 버그: "추천 게시물(FeaturedPost)" 위젯이 메인 페이지의 글 목록을 전부 숨김
홈페이지에서 `Blog1` 위젯의 `.blog-posts` 영역이 완전히 비어 있었음(글이 0개).
`FeaturedPost1` 위젯을 끄니 즉시 정상적으로 글이 표시됨.
→ **FeaturedPost 위젯과 Blog1(기본 글 목록) 위젯을 같은 페이지에 함께 쓰면
Blog1이 깨지는 버그가 있음.** ardentnews 스타일의 "추천 기사" 섹션을 다시 넣고
싶다면 FeaturedPost 위젯 대신 다른 방식(예: 라벨 검색 기반 수동 HTML 가젯)을
검토할 것. **FeaturedPost 위젯은 영구적으로 비활성화 상태로 둔다.**

## ⚠️ 중요 사고 기록 2: 홈/검색 페이지에 글이 1~2개만 보이던 문제 (2026-10-17)

### 증상
홈페이지와 라벨/검색 페이지에서 실제로는 7개 글이 있는데도 1~2개만 보이고
나머지가 잘려나갔음(제목/라벨 복구 이후에도 동일). 브라우저 콘솔에는
`Uncaught AssertionError: goog.dom.insertSiblingBefore expects non-null arguments`
에러가 반복적으로 찍혔음.

### 원인 (두 가지가 겹쳐 있었음)
1. **광고 삽입 로직 충돌**: `Blog1` 위젯 설정의 `showInlineAds: true` /
   `postsPerAd: 3`이 글 목록 사이에 애드센스 광고를 끼워 넣으려 시도하는데,
   이 블로그는 아직 애드센스 승인/연결이 안 되어 있어 광고 슬롯 삽입 스크립트가
   죽으면서 그 이후 글 렌더링이 전부 중단됨.
   - 해결: 테마 HTML 편집에서 `Blog1` 위젯의
     `<b:widget-setting name='showInlineAds'>` 값을 `false`로,
     `<b:widget-setting name='postsPerAd'>` 값을 큰 수(예: 999)로 변경.
2. **글 본문 용량 초과로 인한 서버 사이드 잘림**: 기사당 이미지 3~5장을
   base64로 직접 본문에 삽입해서 글 하나 용량이 180~210KB까지 커졌음.
   Blogger가 홈/검색처럼 여러 글을 한 번에 보여주는 페이지의 위젯 데이터를
   만들 때 응답 크기 제한이 있는 것으로 보이며, 이 때문에 큰 글이 몇 개 섞이면
   나머지 글이 통째로 잘려나감.
   - 해결: **이미지를 base64로 삽입하지 않고 Pollinations.ai 외부 URL을
     그대로 `<img src="">`로 참조**하도록 `scripts/generate_images.py`를
     변경(글 용량이 200KB → 2~4KB 수준으로 감소). 기존 7개 글은
     `scripts/migrate_images_to_urls.py`로 일괄 재생성/교체함.

**교훈: Blogger 글 본문에 이미지를 base64로 직접 삽입하지 말 것.** 이미지는
반드시 외부 URL(이미지 호스팅 서비스)을 참조하는 방식으로 삽입해야
다중 게시물 페이지(홈/검색/라벨)가 정상적으로 전체 글을 보여준다.

### 진단에 사용한 방법
- `document.querySelectorAll('.post-outer-container').length`로 실제 렌더링된
  글 개수 확인 (홈/검색/라벨 각각 테스트)
- 페이지의 `<script>` 인라인 태그 중 `_WidgetManager._SetDataContext(...)`를
  담은 거대한 스크립트를 찾아 그 안의 `'posts': [...]` 배열 길이를 세어
  "서버가 실제로 몇 개를 내려주는지"와 "DOM에 몇 개가 그려지는지"를 분리해서 비교함
  (서버 데이터 개수 < 기대값이면 서버 사이드 잘림, DOM 개수 < 서버 데이터 개수면
  클라이언트 렌더링 크래시로 구분 가능).
